# 내 캘린더 — 개인 캘린더 + 육아 홈·시간표 (Firebase 실시간 동기화)

공용 PC(네이버 웨일)에서도 구글 계정 전환 없이 개인 일정을 따로 관리하고,
아이들의 **준비물·행사·학원 시간표**까지 한 앱에서 보는 웹 캘린더입니다.
**파일 하나(`index.html`)** 로 동작하고, 일정은 **Firebase Firestore(실시간)** 또는
**비공개 구글 시트** 또는 이 브라우저(localStorage)에만 저장됩니다.

**v2.0.0 (2026-11-27)** — 백엔드를 **Firebase Firestore 실시간 동기화**로 바꿨습니다.
PC에서 일정을 저장하면 **휴대폰 화면이 새로고침 없이 0.3초 안에** 바뀝니다.
Firebase 설정은 **⚙ 설정에 붙여넣기만** 하면 되고(콘솔의 `const firebaseConfig = { … };` 통째로),
**Google 로그인을 통과한 본인 계정만** 읽고 쓸 수 있게 잠급니다(보안 규칙 + `users/{uid}` 경로).
저장된 설정만으로는 아무것도 읽지 못하며, 로그인 전에는 달력이 **잠금 화면**으로 가려집니다.
같은 날 **월간 보기에서 마우스 휠**로 이전 달·다음 달을 넘길 수 있게 했습니다(쿨다운 300ms,
편집 창·사이드바 위에서는 동작하지 않음).

**v1.3.2** — 시트를 **연결만 하면 이 기기에만 있던 일정이 저절로 시트로 올라갑니다**
(개인 일정·캘린더·육아 일정·아이 이름). 손으로 「이 브라우저 일정 시트로 올리기」를 누를 필요가 없어
PC와 휴대폰이 어긋나지 않습니다.

**v1.3.1** — 반복 일정의 **요일 다중 선택**(월·수·금), **반복 간격**(2주마다), **반복 기간**(계속/종료일/횟수),
**이 일정만 / 이 일정 및 향후 / 모든 일정** 수정·삭제.

**v1.3.0** — **월 · 주 · 일 · 일정** 보기 탭, 일정 하나만의 **색**, **[✓ 완료]** 흑색 체크리스트.

**v1.2.0** — 아래쪽 탭으로 **👶 육아 홈 · 🗓️ 시간표 · 📅 개인 캘린더**.

## 1. Firebase 실시간 동기화 (권장)

### 왜 Firebase인가

| | 비공개 구글 시트(v1.3.x) | **Firebase Firestore(v2.0)** |
|---|---|---|
| PC에서 저장 → 휴대폰 반영 | 화면을 다시 열 때 / 최대 1분 | **0.3초 안에 저절로** |
| 저장에 걸리는 시간 | 1~3초 | 즉시(기기에 먼저 저장 후 전송) |
| 접근 잠금 | 웹 앱 주소를 아는 사람은 열람 가능 | **Google 로그인한 본인 계정만** |
| 표로 눈으로 보기 | 드라이브 시트에서 가능 | 불가(앱 안에서 JSON 내보내기) |
| 비용 | 무료 | 개인 사용량은 무료(Spark) |

### 처음 한 번만: Firebase 콘솔 설정 (약 5분)

1. <https://console.firebase.google.com> → **프로젝트 추가** (이름은 아무거나, 애널리틱스는 꺼도 됩니다)
2. 프로젝트 개요 화면에서 **앱 추가 → 웹 `</>`** → 앱 이름 입력 → 등록
3. 나오는 **SDK 설정 및 구성**의 아래 덩어리를 **통째로 복사**
   ```js
   const firebaseConfig = {
     apiKey: "AIza…",
     authDomain: "….firebaseapp.com",
     projectId: "…",
     storageBucket: "….appspot.com",
     messagingSenderId: "…",
     appId: "1:…:web:…"
   };
   ```
4. 왼쪽 **빌드 → Firestore Database → 데이터베이스 만들기**
   - 위치: `asia-northeast3 (서울)` 권장
   - 모드: **프로덕션 모드로 시작** (규칙을 아래에서 바로 넣습니다)
5. 왼쪽 **빌드 → Authentication → 시작하기 → Sign-in method → Google → 사용 설정**
   (지원 이메일은 본인 주소 선택)
6. **Authentication → Settings → 승인된 도메인**에 앱을 여는 주소를 추가
   - `localhost` (내 PC에서 파일로 열어 볼 때)
   - `wjoehasa-eng.github.io` (GitHub Pages 주소)
7. **Firestore Database → 규칙(Rules)** 탭에 `firestore.rules` 파일 내용을 붙여넣고,
   `"여기에_본인_구글이메일"` **한 곳만 본인 구글 이메일로 바꾼 뒤 [게시]**
8. 앱의 **⚙ 설정 → Firebase 실시간 동기화**에 3번에서 복사한 설정을 붙여넣고
   **[저장하고 연결]** → **[Google 로그인]**

> 설정을 저장해도 그 자체로는 아무 데이터도 읽히지 않습니다.
> 로그인 창에서 본인 계정을 통과해야만, 그리고 보안 규칙의 이메일과 같아야만 읽고 쓸 수 있습니다.

### 다른 기기(휴대폰·공용 PC)에서 열기

- 설정의 **[이 페이지 링크 복사(#fb=)]** 로 만든 링크를 열면 **Firebase 설정을 다시 칠 필요가 없습니다.**
  (설정은 그 기기 브라우저에 저장되고, **로그인은 그 기기에서 한 번** 하면 됩니다.)
- 한 번 로그인하면 그 브라우저에는 로그인이 유지되어, 다음부터는 앱을 열면 바로 달력이 뜹니다.

### 처음 로그인할 때 (자동 병합)

- 이 브라우저에 이미 일정·캘린더·육아 데이터가 있으면 **id 기준으로 한 번만 합쳐 올립니다.**
  같은 일정이 두 개로 늘어나지 않고, 클라우드에 이미 있는 일정은 그대로 둡니다.
- 다른 기기에서 지운 일정은 이 기기에서도 사라지고, 되살아나지 않습니다
  (이 기기가 클라우드에서 본 적 있는 id는 다시 올리지 않습니다).

### 어떻게 맞추나

- **즉시 반영**: Firestore `onSnapshot` 을 붙여 두어, 어느 기기에서 고치든 **다른 기기 화면이 바로** 바뀝니다.
- **보내기**: 이 기기의 상태가 기준입니다. 바뀐 문서만 `setDoc`, 지운 문서만 `deleteDoc` 으로 보냅니다.
- **오프라인**: Firestore의 로컬 캐시(persistentLocalCache)로 네트워크가 끊겨도 계속 쓰고,
  연결되면 자동으로 올라갑니다. 끊긴 동안에는 연결 칩이 `오프라인 — 이 기기에 저장 중` 으로 바뀝니다.
- **실패 알림**: 저장·삭제가 거부되면(권한·규칙·네트워크) **토스트와 연결 칩에 오류로 표시**합니다.
  조용히 실패하지 않습니다.
- **로그아웃/잠금**: 로그아웃하면 다시 잠금 화면이 되고, 그 상태에서는 **클라우드를 읽지 않습니다.**

### 저장 구조

```
users/{로그인한 uid}/events/{일정 id}          개인 일정
users/{로그인한 uid}/calendars/{캘린더 id}      캘린더(이름·색·표시여부)
users/{로그인한 uid}/kidsEvents/{육아 일정 id}   육아 일정(준비물 체크 포함)
users/{로그인한 uid}/kidsProfile/main           아이 이름·색
```

보안 규칙으로 **본인 uid 아래만** 열려 있고, 이메일이 다르면 거부됩니다.

### 비용

Firebase **Spark(무료)** 한도 — Firestore 저장 1GiB, 하루 읽기 5만 회 / 쓰기 2만 회 / 삭제 2만 회.
개인 캘린더(수백 개 일정, 두 기기)는 이 한도에 거의 닿지 않습니다.
한도가 걱정되면 콘솔 결제를 켜지 않은 상태로 두면 됩니다(한도 초과 시 그날만 쓰기 중지).

## 2. 비공개 구글 시트 (예전 방식, 계속 지원)

Firebase를 쓰지 않아도 되고, **드라이브 시트에 표로 남는 것**이 장점입니다.
Firebase를 켜 둔 동안에는 시트 동기화가 **쉬지만**, 설정에 주소가 남아 있으면
**「📤 구글 캘린더로 보내기」만은 그 시트 백엔드로** 동작합니다(Firebase에는 구글 캘린더 API가 없습니다).

1. 새 스프레드시트를 만들고 이름을 `[비공개] 내 캘린더` 로 정합니다.
2. 메뉴 **확장 프로그램 → Apps Script** → 기본 코드를 지우고 `apps-script/Code.gs` 내용을 붙여넣고 저장.
3. **배포 → 새 배포 → 유형(⚙) = 웹 앱**
   - 다음 사용자로 실행: **나**
   - 액세스 권한: **모든 사용자**
   - 배포 → 권한 승인 → 웹 앱 URL(`.../exec`) 복사
4. 캘린더 오른쪽 위 **⚙ 설정**에 URL을 붙여넣고 **[연결]**.
5. 이미 이 브라우저에 일정이 있으면 연결만 하면 자동으로 시트에 올라갑니다(`v1.3.2`부터).

시트 탭(`일정`·`캘린더`·`설정`·`육아일정`·`육아프로필`)은 처음 호출할 때 자동으로 만들어집니다.
육아 데이터는 `Code.gs` **1.2.0 이상**을 배포해야 오갑니다.

## 되는 것

- **보기 전환**: 상단 **월 · 주 · 일 · 일정** 탭, 단축키 `1/D` 일간 · `2/W` 주간 · `3/M` 월간 · `4/A` 일정 · `T` 오늘

  일정 클릭 → 상세 팝오버(수정·삭제·완료·구글 전송), **끌어서 다른 날짜로 이동**, 2025~2028 한국 공휴일
- **주간 / 일간**: 00:00~24:00 시간 그리드, 현재 시각 빨간 선, 빈 시간 클릭 → 빠른 등록,
  빈 시간 **끌어서 시간 범위 지정**, 겹치는 일정 나란히 배치
- **일정**: 날짜순 목록(오늘부터 1년), 반복·구글 전송 배지
- **일정 편집**: 제목, **종일(새 일정은 종일이 기본 — 시간 그리드에서 만들 때만 시간 일정)**, 시작/종료,
  반복, 캘린더, **일정 하나만의 색**(흑색 포함), **완료**, 장소, 설명
- **반복**: `반복 안함` · `매일` · `매주` · `평일` · `2주마다` · `매월` · `매년` · `맞춤 반복`
  — **요일 다중 선택**, **간격**, **종료 조건**. 표준 RRULE로 저장되어 모든 기기가 같게 펼칩니다.
- **반복 수정·삭제 범위**: 이 일정만 / 이 일정 및 향후 / 모든 일정 (`exdates`·`UNTIL` 로 기억)

## 알아 둘 점

- **알림(푸시) 없음** — 웹앱이라 백그라운드 알림이 불안정합니다. 알림이 필요한 일정만 구글 캘린더로 보내세요.
- **구글 전송은 첫 회차만** — Apps Script가 반복 규칙을 만들지 못해 첫 회차 하루만 복사됩니다.
- **구글 전송은 시트 백엔드가 필요** — Firebase만 쓰는 상태에서는 [📤 구글 캘린더로 보내기]가
  "전송됨" 표시만 하는 시뮬레이션이 됩니다(안내 창이 뜹니다).
- **잠금은 되돌릴 수 없습니다** — Firebase를 연결한 뒤 설정을 잊고 로그아웃하면,
  다시 Google 로그인을 해야 달력이 보입니다. 설정을 지우면(연결 해제) 이 기기 데이터만으로 돌아갑니다.
- 시간 입력은 브라우저 기본 날짜/시간 선택기를 씁니다.

## 개인정보

- 저장소의 코드에는 **실제 개인정보가 없습니다.** Firebase 프로젝트 ID·API 키·이메일·시트 ID는
  코드에 들어 있지 않고, 사용자가 앱에서 붙여넣은 값이 **그 브라우저의 localStorage**(과 `#fb=` 링크)에만 있습니다.
  (Firebase 설정 값 자체는 공개되어도 되는 식별자입니다. 실제 잠금은 Google 로그인 + 보안 규칙이 합니다.)
- 일정은 본인 Firebase(또는 본인 비공개 시트) 밖으로 나가지 않습니다. 광고·분석 도구를 넣지 않았습니다.
- 공용 PC에서는 쓰고 나서 **⚙ 설정 → 로그아웃**을 누르세요. 잠금 화면이 되고 클라우드를 읽지 않습니다.
